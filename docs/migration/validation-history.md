마지막 분류 보완은 서비스 메서드 목록에 문서용 주석을 추가한 변경입니다. 전체 26개 메서드 목록 파일의 문자열 토큰을 대조해 이름·값·순서가 그대로임을 확인하고 문서를 다시 생성했습니다. 실서버 발행·발송·회원가입·탈퇴·결제·환불·실계좌 호출은 수행하지 않았습니다.

보안 검토는 저장소 소스와 도달 가능한 요청·인증 경로를 대상으로 했습니다. 외부 취약점 데이터베이스 대조와 실서버 권한·계정 정책 확인은 포함하지 않았습니다. 레거시 전용 API의 현재 실서버 지원 여부도 확인하지 않았습니다.

전체 미커밋 변경은 이 대화에서 Codex가 수행한 구현·리뷰 작업입니다. 통합 리뷰 시작 시점의 tracked 수정 71개와 untracked 파일 910개도 앞선 구현 단계에서 Codex가 만든 변경입니다. 이어진 리뷰에서 해당 작업 파일 300개를 수정하고 16개를 추가했으며, 홈택스 보기 API 파일 2개를 `search`에서 `view`로 옮겼습니다. 공개 export 이름은 유지했습니다. 생성 문서는 ignore 대상이며 다시 생성했습니다. staged 변경·커밋·푸시는 없습니다.

최종 검증한 코드·설정 내용 해시: `38fb020952b171080d639b8dfe4c64b2896475748447d648a36eb80c83bf369f`.

## 2026-11-03 stub 제거와 modern 기능 동등성 보완

앞선 통합 리뷰 상태를 커밋한 뒤 남아 있던 compat stub Proxy와 adapter를 제거했다. modern에는 세금계산서 레거시 기능, 친구톡 텍스트·이미지 전송, 문자 접수번호별 상태 일괄조회를 추가했다. 세금계산서 PDF의 문서번호 유형도 공식 SDK처럼 매출·매입·위수탁을 받도록 수정했다.

공개 `NotImplementedError` 클래스는 기존 import 호환을 위해 남겼으며 SDK 내부의 생성 경로는 없다. 스키마가 공개되지 않은 문자 상태 응답과 메일 공개키 내용은 `unknown`으로 보존한다. 정적 메서드 대조와 로컬 HTTP mock 검증은 현재 제공자의 실서버 이용 가능성을 보증하지 않는다.

실서버 테스트의 필수 인증·사업자 설정이 실행 환경에 없어 실서버 검증은 수행하지 못했다. 레거시 API의 현재 이용 가능성도 확인하지 않았다. 발행·발송·회원가입·탈퇴·결제·환불·실계좌 호출은 실행하지 않았다.

## 2026-11-03 HTTP 응답 관용성 개선

13개 서비스의 compat·modern 응답 경로와 공통 전송·인증·오류 처리를 검토했다. 숫자 문자열 성공 코드의 판정 차이, 선택 값의 `null → 0/false/"null"` 변환, 새 분류값 삭제, 세금계산서 상태값 때문에 다건 조회 전체가 실패하는 경로를 보완했다. HTTP 오류와 JSON 파싱, 필수 객체·배열 구조의 전제는 유지했다.

문서 응답의 코드·플래그는 입력 타입과 분리했다. 안전한 숫자 문자열과 알려진 불리언 표현은 정규화하고, 미래 코드·미확정 값·`null`은 보존한다. 선택 수량·페이지·파일 크기의 빈 값은 생략한다. 회원·아이디·수집 성공과 탈퇴 후 토큰 폐기는 안전한 정수 비교를 사용하며 원본 결과코드는 유지한다. 오류 정규화도 숫자 문자열을 읽고 원문을 보존한다. 기존 숫자 오류코드의 허용 범위는 줄이지 않았다.
