# 검증 실행 기록

특정 작업 상태에서 실행한 결과를 보관한다. 소스·설정이 바뀌면 과거 결과를 현재 상태의 통과 근거로 재사용하지 않는다. 실행 방법은 [개발 가이드](../development.md), 지원 범위와 제한은 [구현 범위](./service-coverage.md)를 확인한다.

아래 작업에서 실서버 발행·발송·회원가입·탈퇴·결제·환불·실계좌 호출은 수행하지 않았다. 실서버 테스트에는 필요한 인증·사업자 설정이 없었다. 레거시 API의 현재 이용 가능성도 확인하지 않았다. HTTP mock 결과와 실제 제공자 응답·계정 정책 검증은 구분한다.

## 2026-11-03 전체 서비스 구현 완료 시점

후속 통합 리뷰 이전의 결과다.

- 빌드·타입 검사·린트·포맷 검사 통과.
- Node.js 26.10.0·22.22.2에서 각각 테스트 1,376개 통과, 실서버 테스트 94개 건너뜀. Node.js 22 패키지 테스트는 캐시를 재사용하지 않았다.
- 생성 문서: modern 285개·compat 310개, modern 연결 285개, 중복 메서드 0.
- 패키징: 6개 tarball, 전체 공개 import/require, 선언 파일 대응 31개 확인.
- 추가 서비스 CLI 9개의 도움말 실행 통과. 실제 API 호출은 없었다.
- Git diff 공백 오류·staged 변경 없음. 최종 검사 전후 SDK 소스·테스트·문서 생성기의 내용 해시가 같았다.

- 문서 생성기 회귀 검사 9개 통과. 공개 서명 누락·중복·잘못된 compat 연결과 업무 분류를 검사했다.

보안 검토는 저장소 소스와 도달 가능한 요청·인증 경로를 대상으로 했다. 외부 취약점 데이터베이스 대조와 실서버 권한·계정 정책 검증은 포함하지 않았다.

## 2026-11-03 stub 제거와 modern 기능 동등성 보완

compat의 stub Proxy·adapter를 제거하고 modern에 세금계산서 레거시 기능, 친구톡 텍스트·이미지 전송, 문자 접수번호별 상태 일괄조회를 추가했다. 세금계산서 PDF는 매출·매입·위수탁 문서번호 유형을 받도록 수정했다.

- 빌드·타입 검사·린트·포맷·문서 생성 통과, 린트 경고 0.
- Node.js 26.10.0·22.22.2에서 각각 테스트 1,494개 통과, 실서버 테스트 94개 건너뜀. Node.js 22는 패키지 1,475개와 릴리스·문서 19개이며 패키지 테스트 캐시를 재사용하지 않았다.
- 공식 Node SDK 1.64.2의 공개 메서드 308개가 compat에 존재함을 정적으로 대조했다. compat의 바이너리 MMS 확장과 modern의 전송·URL 통합도 확인했다.
- 생성 문서: modern 298개·compat 310개, 연결 298개. 중복·미분류·연결 분류 불일치 0.
- 문서 생성기 회귀 검사 9개 통과. 새 메서드 연결과 문서화되지 않은 응답의 `unknown` 보존을 확인했다.
- 수동 문서 37개의 상대 링크 154개·앵커 13개 확인, 누락 0.
- 버전 1.1.0 manifest와 6개 tarball 확인. Node.js 26·22에서 공개 import/require와 실제 소비자 타입 검사 통과.

공개 `NotImplementedError` 클래스는 기존 import 호환을 위해 남겼으며 SDK 내부 생성 경로는 없다. 메일 공개키 내용과 문자 상태 응답은 공개 스키마가 없어 `unknown`으로 보존한다.

검증한 코드·설정 1,368개 파일의 내용 해시: `3990b008b81ba8eb9fd1fabc0e3c2178bbcf26a089a8efa345fd3c1b4594c571`.

## 2026-11-03 HTTP 응답 관용성 개선

13개 서비스의 compat·modern 응답과 공통 전송·인증·오류 처리를 검토했다. 숫자 문자열 성공 판정, 선택 값의 `null → 0/false/"null"` 변환, 새 분류값 삭제, 상태값 때문에 다건 조회 전체가 실패하는 경로를 보완했다. HTTP 오류·JSON 파싱·필수 객체와 배열 구조의 전제는 유지했다.

출력 코드·플래그를 입력 타입과 분리하고 새 코드·미확정 값·`null`을 보존했다. 회원·아이디·수집 성공과 탈퇴 후 토큰 폐기에 안전한 정수 비교를 적용했다. 숫자 문자열 오류코드를 정규화하되 원문과 기존 숫자 오류코드의 허용 범위를 보존했다.

- 빌드·타입 검사·린트·포맷 검사 통과, 린트 경고 0. 문서 생성기 변경 후 루트 타입 검사·린트·포맷도 다시 통과했다.
- Node.js 26.10.0·22.22.2에서 각각 테스트 1,605개 통과, 실서버 테스트 94개 건너뜀. Node.js 22 패키지 테스트는 캐시를 재사용하지 않았다.
- 응답 경계 회귀 검사에서 숫자·숫자 문자열·앞자리 0·공백·미래 코드·null·누락·안전 정수 범위 초과·금액 정밀도 보존을 확인했다. 세금계산서 다건 조회와 문자 조회는 공개 클라이언트에서 HTTP mock까지 실행했다.
- 생성 문서: modern 298개·compat 310개, 중복 0. `Partial<Omit<...>>` 상속·출력용 타입 재정의·필드 순서·공유 타입 참조를 확인했다. 문서 검사 9개를 Node.js 26·22에서 재실행해 통과했다.
- 패키징: 6개 tarball의 manifest·공개 import/require·소비자 타입 검사 통과. Node.js 26.10.0·22.22.2·24.22.1에서 같은 tarball을 확인했다.
- 독립 리뷰에서 응답 처리·출력 타입·요청 타입 유지·테스트·문서 생성기를 재검토했다. 숫자 문자열의 주변 공백 판정 차이를 추가 수정하고 재검증했다.

경계값은 HTTP mock과 소스 매퍼로 검사했으며 실서버에서 해당 응답 변형은 확인하지 않았다. Node.js 20 소비자 검사는 이 실행에 포함하지 않았다.

검증용 manifest·tarball은 로컬 버전 `1.1.0`이었다. 버전 변경·원격 푸시·배포는 하지 않았으며 이미 발행된 npm 버전을 다시 발행하지 않았다. 검증한 코드·설정 1,370개 파일의 최종 내용 해시: `8f0de53a5044980d1412b49f5b0ac965c5a86c46f70bd89a7ace3911144df78d`.

## 2026-11-03 배포 준비 중 Node.js 20 진입점 검사

후속 검사에서 공식 배포 파일의 SHA를 확인한 Node.js 20.20.2를 사용했다. 앞선 응답 관용성 검증의 같은 tarball 6개를 대상으로 공개 ESM 23개·compat CJS 4개, 총 27개 진입점을 각각 새 프로세스에서 import/require해 모두 통과했다.

이 검사는 패키지 로딩만 확인했다. Node.js 20에서 전체 테스트·소비자 타입 검사·실서버 호출을 실행한 결과는 아니며, 이후 소스·버전 변경에 대한 통과를 보장하지 않는다.

## 2026-11-03 문서 재구성과 공통 로직 정리

수동 문서 전체와 생성 레퍼런스를 재검토했다. 긴 메서드 비교표를 사용 흐름으로 바꾸고, 중복 구현 이력·메타데이터·빈 설명을 줄였다. 설치·인증 준비·필수 입력·결과 조회·실행 예제의 전제를 보완했다. 생성 레퍼런스는 로컬 생성물임을 명시했다.

응답 변환·객체 정리·달력 날짜·클라이언트 타임아웃·multipart 파일명 이스케이프·사용자 콜백 격리는 `popbill-utils`로 모았다. compat 콜백 인자 파서와 modern 오류 adapter는 기존 내부 공통 구현을 재사용한다. 값 보존·필드 순서·오류 문구·콜백 슬롯과 바인딩을 유지하고, 서비스마다 다른 직렬화·검증 정책은 구분했다.

- 빌드·타입 검사·린트·포맷·문서 생성 통과. 생성기 스크립트의 별도 린트도 통과했다.
- Node.js 26.10.0·22.22.2에서 각각 테스트 1,674개 통과, 실서버 테스트 94개 건너뜀. utils 97개와 기존 서비스 회귀 검사를 포함하며 패키지 테스트 캐시는 재사용하지 않았다.
- 문서 생성기 검사 9개 통과. 친구톡 `Pick` 상속 필드 누락과 대표 매핑 없는 API의 잘못된 `legacy-only` 안내를 수정했다.
- 독립 검사에서 DTO 인터페이스 스키마 339개를 TypeScript checker와 대조해 필드·필수 여부 불일치 0. 메서드 608개 서명 보존, JSON 792개 파싱·파일 참조 정상. 생성 Markdown 635개의 상대 링크 1,887개 누락 0.
- 수동 문서 37개와 LICENSE의 상대 링크 235개·앵커 40개 확인. README 예제 10개와 서비스 예제 12개의 공개 타입 검사, CLI 도움말 13개 실행 통과. 실제 API 호출은 없었다.
- 6개 tarball의 manifest·공개 진입점·소비자 타입 검사를 Node.js 26.10.0·22.22.2·24.22.1에서 통과했다. 새 격리 소비자에서 Node.js 20.20.2의 ESM 23개·CJS 4개 진입점 로딩도 통과했다. Node.js 20의 전체 테스트·소비자 타입 검사는 실행하지 않았다.
